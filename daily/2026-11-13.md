### 6.3 What this means for the status key

The 11-12 report raised disk to 🟡 and wrote: *"this log can no longer call 65 % disk use normal,
because 79 % with 92 GB free is a different risk posture for a 460 GB drive."* That was right at
the time and it is now resolved by the user's own action, not by drift. **61 % with 172.8 GB free
is the healthiest reading in seven days.** Back to 🟢.

The lesson worth keeping is about **the metric, not the machine**: this log spent four intervals
tracking "~1 GB/day unattributed growth" that turned out to be ordinary app data, then one
interval tracking a 71 GB install, then one interval watching it leave. **A single-day step on a
460 GB drive says nothing about health.** The right question is the one §6.2 answers — *what is
the biggest tree under the home directory, and when was it last written* — and it takes one
`find`.

### 7.2 700 reaps is a lot of noise about a healthy machine

Every victim is an idle helper: the log's own text is `(idle-exit … rf:- type:daemon)` with idle

The one thing to keep an eye on is **cadence**: 535 (11-11 morning) → 600 in 4 bursts (11-12) →

the PID count. If it keeps climbing through a quiet week, the threshold is being crossed by

Bare `CONTAINS "panic"` returned **7 lines**, and after filtering `panicmedic` the result is

uses a bare predicate will report "panics" on a machine that has none. **Count them, then read
them** — the 11-12 note, unchanged, because it is the cheapest way to be wrong about a crash.
