## 8. Repository changes, the CSV row, and what this run corrected

### 8.1 🔴 `collect.sh` now reports whether the diagnostic store exists

`PANIC_FILES`, `JETSAM_24H` and `DIAG_24H` all return `0` from `find` and `ls` when the directory
they target is missing. That is how a deleted store produced a clean-looking row today. A fourth
key fixes it:

```
DIAG_STORE=present | one-missing | absent
```

It is emitted next to the counters and deliberately **not** added to the CSV schema, so no
historical row shifts; `append_csv.py` ignores keys it does not map. The key exists so the next
run can say "0, and the store was there" instead of "0".

### 8.2 🟡 README: three additions

1. **The power store can be empty, not just short.** The retention section (added 11-22) assumed
   rotation. Today `/var/log/powermanagement` was absent and `pmset -g log` printed one record,
   then none. Check for a *directory*, not just a timestamp.
2. **`DIAG_24H = 0` has a fourth meaning.** The existing note lists "nothing happened", "mid-burst
   sample" and "store reset"; today adds **"store deleted, and the parent rebuilt with an empty
   `CrashReporter` dir"**, which is distinguishable by `DIAG_STORE` and by the parent's mtime.
