### 8.4 Pitfalls re-confirmed

| Trap | Status today |
|---|---|
| `log show --end` without seconds | avoided — every query used full `HH:MM:SS` |
| zsh `log` builtin | avoided — `/usr/bin/log` throughout |
| `CONTAINS "hang"` matching "**C**hang**es**" | avoided — no bare `hang` predicate used |
| Zero-byte result read as "no events" | guarded — the broad probe returned 93 475 lines first |
| `find` without `-xdev` inflating a sweep | **hit once, caught** — see below |

The last one is new and worth writing down. A first pass at the disk sweep ran
`find ~ -type f -size +1M` **without `-xdev`** and reported **2 889 files / 54.8 GB**, which
would have been read as a 50 GB leak. `-xdev` keeps the walk on one filesystem; without it the
search crosses into mounted volumes. The corrected figure is **≈372 files / ≈3.0 GB**.
The sweep output looked entirely plausible, which is exactly why it survived until the category
breakdown did not add up.
